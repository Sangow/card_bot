# Card bot

Telegram-бот [@cardnumber_bot](https://t.me/cardnumber_bot), який зберігає номери ваших банківських карток під короткими назвами, щоб їх можна було швидко скопіювати.

## Можливості

- Додавання, перегляд, зміна номера, перейменування та видалення карток (з підтвердженням).
- Список карток по 5 на сторінку, з маскою й типом картки: `mono •••• 4242 · Visa`.
- Номер у вигляді картки групами по 4 цифри; копіюється натисканням.
- Показаний номер сам ховається через 2 хвилини, а повідомлення користувача з номером і назвою одразу видаляються з чату.
- Увесь діалог (додавання, зміна, перейменування) іде в одному повідомленні бота й продовжується після перезапуску бота.
- Номери карток і дані діалогів зберігаються в БД зашифрованими.
- Не більше 20 карток на користувача.
- Меню команд: `/cards`, `/add`, `/cancel`, `/help`.

## Змінні оточення

| Змінна | Обов'язкова | За замовчуванням | Опис |
|---|---|---|---|
| `API_TOKEN` | так | — | Токен бота від [@BotFather](https://t.me/BotFather) |
| `CARD_KEY` | так | — | Ключ Fernet, яким шифруються номери карток і дані діалогів. Див. [Ключ шифрування](#ключ-шифрування) |
| `DB_PATH` | ні | `/data/db.db` | Шлях до файлу SQLite |
| `LOG_LEVEL` | ні | `INFO` | Рівень логування: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `MAX_CARDS` | ні | `20` | Скільки карток може зберегти один користувач |
| `HIDE_AFTER` | ні | `120` | Через скільки секунд показаний номер ховається |
| `ADMIN_CHAT_ID` | ні | — | Telegram chat id, куди бот надсилає сповіщення про помилки. Без нього сповіщень немає |

На Fly вони задаються як секрети: `fly secrets set MAX_CARDS=30 -a card-bot`.

## Ключ шифрування

> **Якщо ключ `CARD_KEY` загубиться, усі картки всіх користувачів буде втрачено назавжди.** Відновити їх неможливо ні з БД, ні з бекапів.

- Ключ продакшна зберігається в секретах Fly і **в менеджері паролів**. Fly не дає прочитати секрет назад, тож копія в менеджері паролів єдина.
- Згенерувати новий ключ:
  ```bash
  venv/bin/python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```
- Ключ не можна просто змінити: з ключем, яким не зашифровано наявні картки, бот відмовиться запускатися (`CARD_KEY does not match ...`). Це захист від того, щоб у БД не змішалися картки, зашифровані різними ключами.
- Для локального запуску й тестового бота використовуйте окремий ключ, а не ключ продакшна.

## Локальний запуск

Потрібен Python 3.10 або новіший.

1. Створіть **окремого тестового бота** в [@BotFather](https://t.me/BotFather) (`/newbot`). Токен продакшна не використовуйте: два бота з одним токеном конфліктують.
2. Встановіть залежності:
   ```bash
   python3 -m venv venv
   venv/bin/pip install -r requirements-dev.txt
   ```
3. Згенеруйте тестовий ключ (команда вище) і запустіть:
   ```bash
   API_TOKEN=<токен_тестового_бота> \
   CARD_KEY=<тестовий_ключ> \
   DB_PATH=./local.db \
   LOG_LEVEL=DEBUG \
   venv/bin/python app.py
   ```
   Файл `local.db` створиться сам; у git він не потрапить (`*.db` у `.gitignore`).

## Тести

```bash
venv/bin/pytest
```

Тести проганяють справжні апдейти Telegram через диспетчер бота з тимчасовою БД і підміненим Bot API, тож ні токен, ні мережа не потрібні. У CI вони запускаються на Python 3.10, як і в продакшні.

| Файл | Що перевіряє |
|---|---|
| `test_service.py` | Валідація номерів і назв, тип картки, маска, групування цифр |
| `test_texts.py` | Однакові ключі й плейсхолдери в усіх мовах, вибір мови |
| `test_flows.py` | Сценарії бота: додавання, список, сторінки, зміна, перейменування, видалення, ліміт, команди, доступ до чужих карток |
| `test_single_message.py` | Діалоги редагують одне повідомлення бота |
| `test_hiding.py` | Приховування номерів і видалення повідомлень з номером |
| `test_restart.py` | Діалоги переживають перезапуск, дані діалогу зашифровані |
| `test_db.py` | Міграції схеми, шифрування у файлі БД, неправильний ключ |

## Fly.io

Бот деплоїться на [Fly.io](https://fly.io) як застосунок `card-bot`.

## База даних

SQLite у `/data/db.db`.

### Бекап

```bash
fly ssh sftp get /data/db.db ./db-backup.db -a card-bot
```

Номери в бекапі зашифровані, тож без `CARD_KEY` він безпечний. Fly також щодня робить знімки тому й тримає їх 30 днів (`fly volumes snapshots list <vol_id> -a card-bot`).

### Відновлення з бекапу

1. Завантажте бекап на том під тимчасовою назвою:
   ```bash
   fly ssh sftp put ./db-backup.db /data/restore.db -a card-bot
   ```
2. Замініть ним робочу БД і перезапустіть бота:
   ```bash
   fly ssh console -a card-bot -C "mv /data/restore.db /data/db.db"
   fly machine restart <machine_id> -a card-bot
   ```

Бекап має бути зашифрований тим самим `CARD_KEY`, що встановлений на Fly.

```
bot/
  config.py                змінні оточення
  texts.py                 тексти обома мовами, вибір мови
  commands.py              меню команд Telegram
  handlers/
    __init__.py            реєстрація обробників
    user_handlers.py       обробники кнопок, команд і введення
    hiding.py              таймери приховування номерів
    error_handlers.py      глобальний обробник помилок
    service.py             валідація, тип картки, маска
  keyboards/               inline-клавіатури
  sql/
    sq.py                  БД, шифрування, міграції, запити
    storage.py             сховище стану діалогів у SQLite
  states/                  стани діалогів
tests/                     тести pytest
Dockerfile, fly.toml       збірка й налаштування Fly
```
